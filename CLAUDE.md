# BubbleFairy: project notes

A Linux desktop iMessage app: Rust + GTK4 with its own CSS look, shipped as a Flatpak (`io.github.theteknocat.BubbleFairy`). It drives the Mac's `imsg rpc` over SSH (the `russh` library, with the app's own key). Repo: `theteknocat/bubblefairy`, branch `main`, MIT license (Peter Epp). The local folder is still named `imsg-linux`.

- **Read `PLAN.md` first.** It holds the decisions, the phases, the design direction, imsg facts, proof-of-concept gotchas and the open questions.
- Status: feature-complete for 1.0; the app icon is done (`data/icons/.../io.github.theteknocat.BubbleFairy*.svg`, installed by the Flatpak). `PLAN.md` is the frozen design reference; open work is tracked as GitHub issues (labels `priority: low`, `future improvement`, `enhancement`, `bug`).
- Not committed and kept locally for reference until the first build: `poc/imsg-tui` (the working Python/curses proof of concept) and `HANDOFF.md` (its notes, already folded into PLAN.md). Both are excluded through `.git/info/exclude`.
- Mac under test: macOS 26, imsg 0.21.0 from Homebrew at `/opt/homebrew/bin/imsg`. The app itself never uses `~/.ssh`.
- **`docs/LIMITATIONS.md` lists every known limitation (missing features, workarounds, state that doesn't sync).** Keep it current whenever one appears, changes or goes away; it feeds the README and the future help dialog.
- Never put iMessage, Apple or other trademarks in the app name or branding.
- **Privacy features are opt-in only** (off by default, in Settings > Privacy), and where one is off the UI should say how to enable it. This covers only what sends data off this computer to a third party (map and link previews). Local storage such as caches isn't a privacy matter here (the user's own account, their own Mac): those are on by default, with an opt-out setting and a Clear button.

## Build

- The host has no GTK dev packages, so cargo runs inside the GNOME 51 Flatpak SDK: `scripts/dev.sh build|run|test|clippy`. The output goes to `target/sdk/`.
- `scripts/dev.sh` points the XDG dirs at `~/.var/app/io.github.theteknocat.BubbleFairy/{data,config,cache}`, the same folders the real Flatpak will use. Without that, the SDK sandbox throws away anything written to `~/.local`.
- Dev switches: `BF_DEMO=1` (invented chats, no Mac), `BF_SHOT=<file.png>` (save the window after 2.5 s, then quit), `BF_DARK=1` / `BF_LIGHT=1` (force a scheme), `BF_CHAT=<id>` (open that chat), `BF_SHOT_MS=<ms>` (shot delay), `BF_DRAFT=<text>` (prefill the composer, `\\n` = newline), `BF_NEW=<text>` (open the new-message view with that in the To field), `BF_ATTACH=<a:b>` (put files in the composer), `BF_TOP=<n>` (scroll to the top n times, loading older pages), `BF_LINK=<ms>` (keep scrolling to the first link card with a big picture, or to the one whose title has `BF_LINK_TITLE`; use with `BF_TOP`; delete the old shot first, a failed run leaves it behind), `BF_TYPE=<text>` (type into the composer a character at a time, `\\n` = Shift+Enter), `BF_INFO=<ms>` (open the info panel then), `BF_SIDE=<ms>` (press the sidebar button then, narrow window), `BF_TAB=files|links` (with `BF_INFO`: that panel tab), `BF_YT=<video id>` (open the viewer on that YouTube video), `BF_DEMO_FRAME=<picture>` (stand-in first frame for the demo video), `BF_DEMO_MAC=1` (with `BF_DEMO`: loops through connection trouble, offline, Messages access, live updates, chat list, so the status pill and its popover can be watched; sending takes 10 s and shows the slow note, a message starting "fail" fails), `BF_ISSUE=<ms>` (flag a problem then and open the popover), `BF_TOAST=<ms>` (show a toast), `BF_CARD=<ms>` (open the header avatar's popover for the open chat: the contact card, or the people list in a big group; e.g. `BF_CHAT=1 BF_CARD=3000`, `BF_CHAT=6` for the people list), `BF_POPSHOT=<png>` (with `BF_ISSUE` or `BF_CARD`: draw the open popover to a file with `popshot_soon`/`save_widget_png`, since window screenshots leave popups out; use `BF_ISSUE=9500` under `BF_DEMO_MAC` for the connected state). Headless frames: `wlr-randr --output HEADLESS-1 --custom-mode WxH` inside `cage` sets the window size; screenshot paths must be relative to the project (the Flatpak sandbox has its own /tmp). Test HiDPI with `wlr-randr ... --scale 2.5` (also worth testing at 250%). Screenshot runs are NON_UNIQUE so they never hand off to a running copy. For headless screenshots: `WLR_BACKENDS=headless cage -- sh -c "env BF_DEMO=1 BF_SHOT=... scripts/dev.sh run"`.
- **After each change that's ready for Peter to review, relaunch the app yourself** (it's single-instance, so a new launch just hands off to the old copy): `pkill -x bubblefairy; scripts/dev.sh run` with `run_in_background`. Close it before any headless/screenshot run you start.
- `scripts/flatpak.sh` builds and installs the real Flatpak for the user (manifest `flatpak/io.github.theteknocat.BubbleFairy.yml`, local-only: cargo downloads crates; desktop file and metainfo in `data/`); run it with `flatpak run io.github.theteknocat.BubbleFairy`. It shares its data folders with `scripts/dev.sh`.
- GTK CSS `@media (prefers-color-scheme)` did not fire for an app provider (GTK 4.24), so dark mode is a `window.dark` class set from `gtk-interface-color-scheme` in `ui.rs`.

## Code standard and lint exceptions

- Config: `rustfmt.toml` (edition 2024, `max_width = 100`, `use_field_init_shorthand`) and `[lints.clippy]` in `Cargo.toml` (`dbg_macro`, `todo`, `unwrap_used` on top of the default set). `clippy.toml` exempts test code from `unwrap_used`. Before committing: `cargo fmt`, `cargo fmt -- --check --config error_on_line_overflow=true` (prints nothing; plain `--check` silently skips a block it can't fit in 100 columns, such as a `select!` body or a long attribute, which are wrapped by hand), `scripts/dev.sh clippy --all-targets` and `scripts/dev.sh test`, all clean. CI (`.github/workflows/ci.yml`) runs both fmt checks, the same Clippy with `-D warnings` (in the GNOME SDK, like `scripts/dev.sh`) and the tests on every push to `main` and every pull request. First `cargo fmt` of an old file goes in its own commit.
- Exceptions are `#[allow(...)]` as narrow as possible with a one-line reason beside them, so `grep -rn "allow(" src` lists them all. Today: `unwrap_used` for `Mutex::lock().unwrap()` (module level in `mac.rs` and `setup.rs`, one statement in `ui.rs`: a poisoned lock means another thread panicked, so crashing shows the bug), `demo.rs` (dev-only fixtures), and `deprecated` on one `Texture::for_pixbuf` call. Other `unwrap`s were replaced with `if let` / `?`.
- Doc comments are `///` with a one-line summary first; no `@author`-style tags. Repeated code is made DRY (one helper, a test if the logic is risky) unless there is a major trade-off.
- Audits: `docs/ponytail-audit-YYYY-MM-DD.md` (a second run the same day gets `-2`), each finding logged with its fix or skip reason, one commit per round; the log ends with a "Not read" list that sets the next scope. Round 1 (2026-11-22) covered `mac.rs`, `setup.rs`, `webpreview.rs`, `snapshot.rs`; round 2 the places where a sender's content reaches this computer (links, saves, notifications, cache pruning). Helpers from it: `safe_name` (sender file names), `is_group_event`.
- Releasing: bump `version` in `Cargo.toml` (and `Cargo.lock`) and add a `<release version date>` line at the top of `<releases>` in `data/*.metainfo.xml`, commit, push `main`, then push a `vX.Y.Z` tag. The tag push runs `.github/workflows/release.yml` (~15 min): it fails unless the tag matches the Cargo.toml version, builds the Flatpak bundle and creates the GitHub Release with `BubbleFairy-vX.Y.Z.flatpak` and generated notes (`workflow_dispatch` = test build, no release). Then `scripts/flatpak.sh` reinstalls the user's local Flatpak. Check with `gh run list`.

## Layout

- `src/main.rs`: paths, config file (`key=value` lines), tokio runtime, GTK app startup, CSS loading.
- `src/mac.rs`: backend. `run()` loops connect → serve → reconnect every 5 s. `connect()` resolves the host (plain DNS, then mDNS for `.local` names, because Flatpak runtimes lack nss-mdns), checks the host key (trust on first use, stored in `mac_host_key`), authenticates with the app's ed25519 key (`ensure_key` creates it), execs `<imsg> rpc`, and runs a writer task and a reader task. `dispatch` routes JSON-RPC replies to pending calls and `message` / `watch.overflow` notifications to `Event`s. Images are fetched on separate exec channels with `sips` → JPEG.
- `src/ui.rs`: every widget and all state, on the GTK thread. `on_event` handles backend events, and `render_chats` / `render_conv` rebuild the list and the conversation from state. Only flags that signal handlers touch are kept in `Cell`s, to avoid RefCell re-borrow panics (selecting a row fires `row-selected` synchronously).
- New conversation (ui.rs `start_new`/`end_new`/`send_new`): `new_mode` hides the chat header and messages for a To field plus a suggestions ListBox of 1:1 chats. A typed address sends `Cmd::Send{chat_id: 0, to}`; `State.new_pending` opens the chat when `Event::Chats` lists it (`find_direct_chat`, `same_addr`).
- Older chats: imsg's `chats.list` has only `limit`, no offset, so scrolling the sidebar to its end (`load_more_chats`, adjustment in `build`) asks again for `State.chat_limit` + `CHATS_PAGE` (100) chats and the answer replaces the list (rebuild, scroll kept); `more_chats` goes false when an answer is shorter than the limit. Gotcha: a pinned chat older than the loaded limit has no tile until more are loaded.
- Receipts: `Cmd::Receipts(chat)` reads the delivery / read columns of the chat's newest sent message from chat.db (`parse_receipt`); `State.receipts`, drawn by `conv_widgets` as a small label under that message (`receipt_text`; a red "Not delivered" under any sent message whose chat.db `error` is non-zero, which `add_services` adds to every message), `on_receipt` redraws only the affected messages.
- Times: `rel_time(unix, TimeKind)` is the only formatter; labels showing a time are created through `track_time` (kept in `Ui.time_labels`, rewritten by `refresh_times` at midnight / when the window becomes active on a new day), so a day change needs no rebuild. Failed messages (chat.db `error` != 0): red "!" (`failed_button`) → Try Again → `retry_failed` → `Cmd::Resend` (attachments by their Mac paths), the failed one stays in place (ghost + spinner via `State.resending` while it runs, outline "!" afterwards via `State.resent`, file `resent`); a retried picture's texture is handed to the new message through a `PendingItem::Seed`.
- Read state: `mac::fix_unread` corrects imsg's unread counts from chat.db; `State.seen` (file `data/bubblefairy/seen`) hides dots for chats read in BubbleFairy (`mark_seen`, only while the window is active, so headless runs never mark anything).
- Sending files: `State.outgoing` + `render_attach` (cards above the composer); `pick_files`, a DropTarget on the conversation and `paste-clipboard` add them. `mac::upload` pipes each file into an exec channel (`cat >`) and `send_one` sends it; `Event::Sent` hands back whatever didn't go.
- Pending sends: `send_now` pushes `State.pending` (`Pending{token,chat_id,item}`), `render_conv` draws them faded with a spinner (`pending_bubble`); `settle_pending` (in `on_message`) swaps in the real message and seeds `State.textures` from the local file so the photo shows at once; `Event::Sent` error → `drop_pending` + restore the composer, success → 20 s fallback drop.
- Composer height: set from a Pango layout of the text at the TextView's width (`fit` in `build`), not from the TextView's measure, which ran a line tall while new lines were laid out. Capped at `COMPOSE_MAX`, then scrolls. While it all fits, the vadjustment is pinned to 0: a key press that adds a line scrolls the TextView to the cursor before the field grows, leaving the text ~10 px high. Simulated typing (`BF_TYPE`) doesn't reproduce that.
- Link previews: `preview_row` finds the preview row (imsg folds it into `url_preview`); `link_for` asks the Mac once (`Cmd::Link` -> `mac::link_preview` parses the NSKeyedArchiver plist); Preview pictures under 400x200 px (site logos; Messages shows those as icons too) are measured on the Mac with `sips` (`LinkPreview.image_size`, `is_preview_size`) and drawn small beside the title (`Bubble::thumb`, whole logo on a white tile) instead of across the top. `link_card` draws it as one `Bubble::card` (off-white, image clipped to the bubble outline in bubble.rs; `without_url` strips the link from the message text, which follows as its own bubble). Payload files go through `sips` only: Quick Look hangs on `.pluginPayloadAttachment`, and `fetch_image` has an 8 s watchdog on qlmanage. Photos still need Quick Look because `sips` ignores HEIC rotation (most test HEICs came out sideways).
- Avatars: `mac::fetch_contacts`/`parse_contacts` read the Mac's Contacts photos once per connection (`Event::Contacts`); `ui::avatar` draws a `Bubble::disc` photo when `photo_for(handle)` finds one (`addr_key` = lowercase email or last 10 phone digits), else `initials_avatar` (a person icon when the name has no letters); groups use `group_avatar` (member circles in a disc, three plus a "+N" circle past four) in lists and `stacked_avatars` (overlapping row, first on top, "+N" past four) in the conversation header; `pretty_handle` formats +1 numbers everywhere a handle is shown.
- Contacts search and cards: `mac::Contacts` also holds `Person`s (name, org, numbers/emails with labels, postal addresses, birthday; addresses and birthday come from a separate query so a wrong column loses only those), `search()` feeds the To field's suggestions (`ui::suggestions`, contacts without a chat get `a:<addr>` rows), `label()` gives the "mobile/work" chip, `has_imessage()` is true only when chat.db has an iMessage handle for it (registration itself can't be asked). The header avatar opens `show_card`/`card_body`, or in a big group the people list (`show_people`). Both come from `anchored_popover`: a Popover with the `issues` class shared with the status popover, parented to the window (parented to a Box it pushes the header's children over). The card sits in a ScrolledWindow capped to the room below. Email opens through `gtk::UriLauncher` (`gio::AppInfo::launch_default_for_uri` gave Thunderbird `mailto:///addr`). Our own icons live in `data/icons` (`chat-message-new-symbolic` renders as a red missing-icon glyph in the SDK; added to the icon search path in `main.rs`, needs installing under share/icons in the Flatpak).
- Info panel (ui.rs `build_info`/`wire_info`/`open_info`/`refresh_info`/`on_media`): header "i" button opens an opaque panel that always slides over the chat's right side (never pushes the chat, never widens the window); a click anywhere outside it closes it (window-level capture gesture). Photos / Files / Links tabs, read from chat.db by `mac::chat_media` (`Cmd::Media{kind,offset}`, 30 photos or 60 others a page, "Show more"). Header row (tabs + close) is fixed and only the tab content scrolls; the tabs are our own linked ToggleButtons (StackSwitcher measured far too wide), and at 1 column they become `‹ Photos ›` carets with an invisible twin of the close button so the label stays centred. `info_w(n)` is the slot width for n photo columns (grid cell measures THUMB + 6, header minimum 263 / 223 caret row; CSS margins count inside `set_size_request`), `relayout` picks the largest n that fits over the chat. Thumbnails use `Cmd::Bulk` (2 at a time) so they can't starve the chat's own fetches. Photos/files not on the Mac are marked `missing`. Files download over SSH (`Cmd::Download`) into the cache's `files/` and open with `gtk::FileLauncher`. The Links tab lists only messages with a Messages preview or exactly one trailing link (`mac::single_link`); text comes from `message.text` or the `attributedBody` blob (`text_from_blob`). The header refresh button reloads the loaded messages (`refresh_chat`).
- Pinned chats (ui.rs `pin_key`/`pin_menu`/`toggle_pin`/`render_tiles`): our own list in `data/bubblefairy/pins` (chat `identifier`, one per line, pin order). Pinned chats stay in `chat_list` as *hidden* rows (indexes must match `State.chats`) and show as avatar tiles in `src/tilegrid.rs` (our own widget, replacing FlowBox; 3 per line, one column when collapsed; drag a tile to reorder, saved by `reorder_pins`; GTK caches a height asked without a width, so it calls `queue_resize` when its column count changes) above it inside the sidebar scroller; right-click a row or tile → Pin/Unpin. Pin/mute keys: `keys_of`/`pin_pos`/`is_muted` match any identifier of a merged chat. Dev: `BF_TILE_DRAG=<ms>`, `BF_PEOPLE=<ms>` (big-group people popover). Dev: `BF_PINS=<key>;<key>` (demo keys = participants joined by `,`). Sidebar search: `search`/`apply_search`/`row_matches` (a `gtk::ListBox` filter func; pinned chats' hidden rows are shown while searching, tiles hidden; dev: `BF_SEARCH=<text>`). Drafts: `swap_draft` in `select`, `State.drafts`.
- Smoothness (the app rule: no hitches): the GTK thread only builds widgets. `bg()` (ui.rs) runs file reads and picture decoding on two worker threads and hands the result back (`decode_file`, `image_done`; contact photos: `prefetch_avatars`/`decode_avatar`, 128 px). A photo on disk shows after a background decode (no spinner), one not on disk gets a spinner and a fetch. `render_conv` builds the whole page in one pass (~28 ms for 150 messages with the pictures decoded elsewhere; building the newest part first and the rest after, in steps or in batches, was tried and only added complexity and a loop that kept loading older pages). The list's preview updates and `mark_seen` change one row in place (`update_row`, `RowParts`); only structural changes rebuild it (`render_chats`, burst-coalesced with `render_chats_soon`). Don't scale while decoding with gdk-pixbuf (`Pixbuf::from_file_at_scale` in a worker made GTK-thread work stall ~20 ms): the Mac sends 900 px chat copies (`mac::CHAT_PX`) instead. Text bubbles use wrap mode `Word`, not `WordChar` (3-4x cheaper to lay out; 150 labels were ~150 ms of the first frame): `WordChar` only when a word is over 30 chars (links). A link preview arriving redraws that one message (`redraw_message`, from `conv_ctx`/`msg_widgets`), not the chat. Headless (llvmpipe) frame times say nothing about paint cost; time your own handlers instead, and the frame clock's phases (`connect_update`/`layout`/`paint`) to see which part of a frame is long.
- Responsive layout (`relayout` in ui.rs, run from a tick callback on width change): window minimum is `COLLAPSED_W + CHAT_MIN`. Below `SIDEBAR_MIN + CHAT_MIN` (700) the sidebar shows avatars only (`COLLAPSED_W`); the header toggle (own `bf-sidebar-symbolic` icon) expands it over the window (divider at width − 8 so its right margin is 14 like the left; the chat fades via `.conv.away`), and the expanded state is forgotten when the window crosses the line. Crossing and the toggle slide the divider (`move_side`, 220 ms). Rows are never rebuilt between modes: each is an Overlay (a `stack` of avatar + short name, its width `stack_w`; texts in a clipped `row-slot`, faded out when collapsed), so only the sidebar width, the `collapsed` class and those widths change; collapsed items are rounded rectangles with the name (`short_title`) under the avatar, margins 4 so they and the pin tiles line up, avatar at the same x in both modes; "…" truncation (`text_target`/`fit_texts`) is recomputed only after a slide settles. Gotchas: anything that raises the sidebar's minimum width above the divider position at the start of a slide (margin changes, wider header buttons, the loading label in the stack) makes it jump left, so header button margins are constant; keep `side_stack` non-homogeneous.
- Links in chat: `message_parts` shows a preview card when Messages made one; a single trailing link with none becomes `plain_link_card` (host + our link icon `bf-link-symbolic`); several links stay in the text, clickable (`linkify`). `small_picture` picks the larger of the preview's picture and the site icon for the small slot (a very wide picture such as a button graphic loses). Pictures the Mac couldn't give us go in `State.bad_images` and the preview is redrawn without them. Logos draw at their own size or shrunk, never enlarged (`Bubble::thumb`); grid thumbnails are `Bubble::tile`. `Bubble::card` caps its own width (`card_w`) and must set `hexpand(false)` or the title's expand flag stretches it. `watch_for_preview` re-fetches the newest messages (`Cmd::Recent`) at 3/8/20 s for a message whose link has no preview yet. Messages built through AppleScript sends may never get a preview.
- Files in chat (`message_parts` → `file_card` / `video_preview`; info panel Files tab → `file_tile`, a grid like Links): `FileKind` (from MIME, else extension) gives the label and our own icon (`bf-file/video/audio/contact/archive-symbolic`). A file is an off-white `Bubble::card` like links (title = name, `link-site` line = kind · length · size, picture/`glyph(icon)` on the right); a video on the Mac is a photo-sized first-frame `Bubble::photo` with a play disc and length pill; not on the Mac = dimmed, not clickable (imsg can't make the Mac download anything). Clicking copies it over SSH and opens it (`start_download`, shared cache with the panel). What the Mac can give: chat.db has only name, MIME/UTI, size, date (no previews when missing; `transfer_state` is unreliable, check the file); Quick Look (`fetch_image`) draws a PDF's first page and a video's first frame; audio gets only a generic note and vCards hang it, so those use our icon; `Cmd::FileInfo` runs `afinfo` for durations and reads vCard FN/ORG/TEL (`FileInfo`, asked once per file, `State.file_info`, chat redraws on arrival). The Mac has no `timeout` command. Card titles go through `clip_middle` (not label `lines` + ellipsize: that made cards wider than their cap).
- Tray (`src/tray.rs`, ui.rs `start_tray`/`stop_tray`): automatic whenever a tray host exists (`tray::host_present`: StatusNotifierWatcher on the bus); the only setting is login start (Settings > Background, config `autostart`; no host = starts minimized, the label and help text change). A `--tray` start retries the tray for ~10 s before falling back to a minimized window. First close into the tray sends a one-time notification (`tray_hint`, file `data/bubblefairy/tray-hint`); Ctrl+Q quits. One StatusNotifierItem per run (`Ui.tray`), `Ui.hold` keeps the app alive with the window hidden, `connect_close_request` hides instead of quitting while it exists. Unread dot: `update_title` sets `Tray.unread` (NeedsAttention, `...-unread-symbolic` icon). Login entry: Background portal via `ashpd`, command `--tray`.
- Address maps on contact cards: Settings > Privacy `map_previews` (default off: privacy settings are opt-in only); the Mac's curl asks OpenStreetMap, off = a button that opens the maps app (`ui.rs` around `open_map`).
- Settings (`settings`, `mac_tab`, `tab_switcher` in ui.rs): two tabs (Settings; Mac connection, read only, with "Set up again…"). `tab_switcher` is also the info panel's tab bar (`.bf-tabs`). Dev: `BF_SETTINGS=<ms>`, `BF_SETTINGS_TAB=mac`, `BF_SETTINGS_SHOT=<png>`.
- `src/setup.rs`: the first-run wizard (backend `Link` over russh with password or key login, `discover` mDNS scan, `imsg_zip` bundled-or-downloaded with a SHA256 check; GTK wizard `open_wizard`, called by `ui::start_setup`, linear async flow with `rt(fut)` hopping to tokio). Dev: `BF_SETUP=1` (open it), `BF_SETUP_TEST=1` (throwaway key + `BubbleFairy-test` folder on the Mac, nothing saved), `BF_SETUP_HOST=<host>`, `BF_SETUP_INTRO=1` (force the welcome page), `BF_SETUP_PAGE=<n>`, `BF_SETUP_AUTO=<mac user>` (clicks through pages 1-3), `BF_SETUP_KEYLOGIN=1` (sign in with the app's key, no password), `BF_SETUP_SHOT=<png>` + `BF_SETUP_MS`, `BF_SETUP_LOG=1`. Never send a real test message from automation.
- `src/chatscroll.rs`: the chat's scrollable (a `gtk::Scrollable` subclass replacing Viewport), anchored to the bottom: it keeps the gap between the view's bottom edge and the content's end (or stays at the bottom while `stuck`, shared with `Ui.stick_bottom`) inside the same layout pass, so older messages, late pictures and a growing composer never shift what you're looking at. Only the user's own scrolling changes the gap.
- `src/bubble.rs`: `Bubble`, a gtk::Box subclass that draws its own background as one GSK path (body + tail): gradient fill, shadow, top highlight and border all follow the tail. GTK CSS has no clip-path or pseudo-elements, which is why. Colours are in `palette()` (light/dark, read from the window's `dark` class). Inner spacing is set with margins in `new()`, because CSS padding didn't apply to the subclass. Content goes in with `Bubble::add`.
- Photos are `Bubble::photo`: the photo is drawn through the bubble outline, so a photo that ends a sender's run gets a tail showing a sliver of the image. The tail goes only on the run's last item (`end_of_run` in `message_parts`). Every bubble has the same corner radius (no neighbour joining); name and avatar follow the run (`run_prev`/`run_next`), and runs get a tight gap.
- `src/viewer.rs`: photo viewer, a panel of its own in a `stage` Overlay over the whole paned area, edge to edge with the sidebar/chat margins (14 px sides and bottom, 2 px top), 22 px corners, no bevel; the window gets class `viewing` while it's visible, which drops the other panels' shadows/bevels. `Canvas` zooms the photo from its chat spot (`source_rect`) to edge-to-edge fit (240 ms). Items are `(path, Bubble)` from `State.photos`; `refresh()` after every `render_conv` re-finds the current path. Chat copies are capped at `mac::CHAT_PX`; one that hit the cap triggers `Hooks.fetch_full` (`Cmd::Image{full:true}`, `mac::FULL_PX`, cached as `<hash>-full.jpg`) with a canvas spinner until `full_ready`. Items are `viewer::Item` = (key, widget): photos/videos keyed by path (widget = their `Bubble`), YouTube links keyed `yt:<id>:<n>` and played in an embedded WebKit view (`play_youtube`, ephemeral session, `fs=0` etc., web view starts 56 px down so our buttons have their own strip). `ui::open_media` builds the sequence: in the chat = `State.photos` (photos, videos and YouTube cards in order), in the info panel = `info_sequence` (photos + Videos tab tiles, newest first, read back from tiles' widget names `<date>|<key>`). Bounded prev/next (buttons, ←/→, one wheel notch = one item) over loaded items only; it never loads older history (a design decision). Controls get class `controls` on real pointer motion and drop it after 2.5 s. Keys come from a window-level capture controller in `ui::build`. Dev: `BF_VIEW=1` opens it 0.9 s before `BF_SHOT`, `BF_VIEW=<ms>` at that time (real chats need ~5500).
- Stacks (`photo_stack`): several photos in one message become a card stack (first on top, the rest peeking away from the message's side). Resting spacing is `CARD_STEP` capped to fit; hover spreads to the full chat width (`stack_room`, from the scroller's hadjustment page size), at most side by side. `Ui.stacks` re-lays them when the width changes.
- `src/style.css`: the whole look. Palette tokens live on `:root`, with dark overrides on `window.dark` (`var()` needs GTK ≥ 4.16).
- Saving (ui.rs `save_button`/`save_items`/`queue_save`/`copy_to`): download button beside photos/videos/files, right-click on photos = Copy image / Save as…; folders in config `dir_images`/`dir_files` (Settings group), stored as document-portal paths (field shows the `user.document-portal.host-path` attribute); `State.save_to` holds saves waiting for `Event::Downloaded`; an unusable folder falls back to the dialog.
- Reads from the Mac (mac.rs `cli`): chat list, history, previews, older/newer pages and the search window run `imsg ... --json --no-contacts` as one-off commands (imsg looks up every contact on every call, ~1.2 s, and RPC has no switch for it); names/photos come later from our own Contacts reading and are applied in place (`ui::refresh_identities`, `rebuild_tiles`), never by rebuilding the list. The RPC channel is only for send and watch. sqlite3 on the Mac prints control characters as `^_`, so use printable separators (⁂) in queries.
- Name search: `search_changed` also sends `Cmd::FindNamed{q, addrs}` (addrs from `Contacts::search`); `mac::find_named` reads chat.db for groups whose name matches or chats with those members (items with real messages only, 15 max); `Event::FoundNamed` inserts the unloaded ones (`insert_chat`, `fill_names` for their people, `apply_search`).
- Message search (ui.rs `search_changed`/`on_found`/`style_rows`/`begin_find`/`show_goto`/`load_newer`, mac.rs `Cmd::Search/Window/Newer`): see PLAN.md. A chat opened on a hit has `State.find_view` (window around the hit, `more` = newer messages not loaded, so live messages aren't appended); `show_goto` re-finds the target widget every frame for 1.8 s because redraws and late pictures move it (chatscroll is bottom-anchored; `ChatScroll::hold` keeps the view when pages are added below).
- Search behaviour (ui.rs `search_changed`/`on_found`/`exit_search`): the chat open before a search stays on show; a chat clicked from the results is `State.search_pick` and follows later searches (`on_found` re-opens it on its first hit or closes the bar). Hits in chats outside the loaded list: `Cmd::FindChats` fetches them (`State.search_added`, dropped again by `exit_search`); a picked chat that wasn't in the list stays in `State.chats` with a hidden row (`off_list`) until scrolling loads it. `match_sql` also matches attachment names and the preview payload. Gotchas fixed once: `pin_menu`'s closure must hold its widget weakly (a strong ref leaked every rebuilt row), and `TileGrid::measure` must not use the width of a hidden widget (0).
- Search field and highlights: the field lives in the header (`search_wrap`/`search_btn`/`search_place`/`search_to`, ✕ always shown, magnifier click closes), so search works with the sidebar collapsed; result rows show a count pill (`.count-pill`) or, collapsed, a badge. Highlights: `highlight` finds whole-word spans (`word_spans`, consecutive words merged) and `src/pilllabel.rs` paints pink pills with a shadow under the label (GtkLabel can't be subclassed: the first highlight moves the label into a pass-through `Host` widget; `mark_labels` collects labels before highlighting); matched text is bold; ellipsized labels skip pills for matches that aren't fully visible.
- The sidebar doesn't load more chats while the search box has text (the filtered list is always "at its end": the loads chained and froze the app). Newer-message paging is by date (`page_after`), never by row id: messages synced later have a high row id and an old date.
- Plain-link previews (ui.rs `web_preview`, `webpreview.rs`): off unless config `link_previews`; fetched by this computer through `webkit6::soup` (no HTTP crate); the GNOME runtime has no gdk-pixbuf loaders, so picture sizes come from `webpreview::image_size`. A parse miss is stored as `failed` in `web_links` and not retried: delete the line to retry (also how a preview saved before the page icon was added gets one). The page's icon (`webpreview::pick_icon`, `fetch_web_picture`) is saved as `icon`/`icon_size`; `small_picture` picks it for the small slot when it beats the picture. YouTube serves its tags ~800 KB into the page (hence the 2.5 MB read cap).
- Preview widths: every preview in the chat (photo, video frame, link card, file card) is `MEDIA_W` (300) wide, like Messages; photos scale up as well as down (small ones may look soft) and only a shape taller than 2.2x the width is narrowed (`show_texture`). Stacked photos stay square cards.
- Replies and mute: `conv_widgets` draws the original in a small bubble above a run of replies plus "N Replies" under the original (display only; threaded sending needs SIP off). Muted chats are our own list (`State.muted`, file `data/bubblefairy/muted`, `toggle_mute`, in the same right-click menu as pins); `notify` skips them. Messages' own mute list has hashed 1:1 keys we couldn't match. Dev: `BF_DEMO_REPLY=1`.
- Local copy (`src/snapshot.rs`; ui.rs `load_snapshot`/`snapshot_soon`/`clear_snapshot`): the chat list (first `CHATS_PAGE` of `raw_chats`), their previews and the Mac's raw contacts text (`Contacts.raw`, re-read by `parse_contacts`) are saved in `cache/bubblefairy/{chats,contacts}.json`, tagged `user@host` + a version. On start `load_snapshot` replays them through `on_event(Event::Contacts/Chats)` so the first frame is named, merged and has photos; the Mac's answers replace them (`State.contacts_cached` makes `Event::Connected` ask for fresh contacts anyway). Saved 3 s after a change (`snapshot_soon`, from `update_row` and `Event::Chats`), cleared by "Set up again", by Settings > Faster start (`local_cache`, default on) and its Clear button. Not saved: message history (the open chat's pane stays empty until connected).
- Merged chats (ui.rs `merged_chats`/`set_chats`/`after_merge`, mac.rs `Merged`/`members_of`/`canon_of`/`history_of`/`Cmd::Merge`): one person's 1:1 chats (found through the Contacts: `Contacts::person_id`; for non-contacts, or before the Contacts load, the same number/email via `merge_key`) are one sidebar entry, the newest chat's entry with the oldest's id (stable), unread summed, `merged` = all ids, `pin_key` = the oldest's key (pins/mutes migrate). `State.raw_chats` keeps imsg's list; re-merged when Contacts arrive. The backend reads history/search/receipts/media across every member and sends to the newest; messages come back with `chat_id` rewritten to the merged id. Group chats are not merged. `Cmd::Merge` is applied in `mac::run`'s command loop (`apply_merge`), not in a spawned task, so a history read sent right after it can't run first (it showed only the oldest chat's messages). Chats beyond the loaded 100 merge only once they load (earlier merging at open time was judged not worth the complexity).
- Group events (`item_type` != 0 from `add_services`, with `event`): drawn as centred lines by `group_event` (left/removed/added/renamed); never a preview, never a chat's date (`fix_last_message` dates and re-sorts group chats by their newest real message). `add_services` also adds the Siri flag (`siri`, shown under received messages only) and the service/error. Watch for NULL columns in its SQL: one NULL voids the whole line (use `coalesce`).
- Problems and toasts (ui.rs `set_issue`/`status_clicked`/`show_toast`/`set_status`, mac.rs `Event::Issue`/`ChatsFailed`/`SendSlow`): there is no banner. What's wrong with the connection is `Ui.issues` (kind -> text; kinds `offline`, `chats`, `access`, `stopped`, `live`); the status pill is green, red (offline) or orange "Needs attention" (connected with issues), and clicking it opens a popover: a title with a dot, any issues, and while connected the Mac, account, connected-since (`Ui.since`) and last-heard (`Ui.heard`, stamped in `on_event` by anything from the Mac) fixed width (`STATUS_POP_W`), arrow styled in `popover.issues > arrow`, redrawn live while open (`status_pop`, `fill_status_pop`, from `set_status`/`set_issue` and a 5 s timer for the times) with an icon-only refresh button (re-asks the chat list and the open chat). The pill is only a light (no text, so it never changes width and the popover stays put): its words are the tooltip, the accessible name and the popover title (`Ui.status_title`; `status_tip` the reason shown under it). The backend sends `Issue(kind, Some|None)` on every connect, so a cleared one goes away; setting an unchanged issue changes nothing on screen (no flash); `Event::Chats` clears `chats`, `Connected` clears `offline`. A send taking over 6 s puts `State.slow` (by token) and a note under its last pending bubble, styled as `.receipt` like "Read" (`append_pending`). Errors from something the person just did (not sent, save/copy failed, login entry, the "Who's it to?" hint) are an 8 s toast over the window's top (`show_toast`).
- Notifications/sound: `notify` in ui.rs (settings in `Config`: notify, notify_sound, sound, notify_text), `src/sound.rs` (GStreamer `playbin`, bundled WAVs in `data/sounds` from `scripts/make_sounds.py`, found next to the sources or under share/bubblefairy/sounds), `desktop_inhibited` asks the notification service about do-not-disturb. Window in front: an incoming message plays `data/sounds/received.wav` (no desktop notification) and sending plays `sent.wav` (`sent_sound`); both are hand-picked files, not made by `make_sounds.py` and not in the Settings list; window not in front: notification + sound. Dev: `BF_DEMO_INCOMING=<ms>`, `BF_SOUND`, `BF_SOUND_LOG`.
