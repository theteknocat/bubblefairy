# BubbleFairy: project notes

A Linux desktop iMessage app: Rust + GTK4 with its own CSS look, shipped as a Flatpak (`io.github.theteknocat.BubbleFairy`). It drives the Mac's `imsg rpc` over SSH (the `russh` library, with the app's own key). Repo: private `theteknocat/bubblefairy`, branch `main`, MIT license (Peter Epp). The local folder is still named `imsg-linux`.

- **Read `PLAN.md` first.** It holds the decisions, the phases, the design direction, imsg facts, proof-of-concept gotchas and the open questions.
- Status: Phase 1 and most of Phase 1.1 are built; see the top of `PLAN.md` for what's left and what hasn't been checked on a real run.
- Not committed and kept locally for reference until the first build: `poc/imsg-tui` (the working Python/curses proof of concept) and `HANDOFF.md` (its notes, already folded into PLAN.md). Both are excluded through `.git/info/exclude`.
- Mac under test: macOS 26, imsg 0.21.0 from Homebrew at `/opt/homebrew/bin/imsg`. It can be reached with `ssh mac` from Peter's terminal. The app itself never uses `~/.ssh`.
- Never put iMessage, Apple or other trademarks in the app name or branding.

## Build

- The host has no GTK dev packages, so cargo runs inside the GNOME 51 Flatpak SDK: `scripts/dev.sh build|run|test|clippy`. The output goes to `target/sdk/`.
- `scripts/dev.sh` points the XDG dirs at `~/.var/app/io.github.theteknocat.BubbleFairy/{data,config,cache}`, the same folders the real Flatpak will use. Without that, the SDK sandbox throws away anything written to `~/.local`.
- Dev switches: `BF_DEMO=1` (invented chats, no Mac), `BF_SHOT=<file.png>` (save the window after 2.5 s, then quit), `BF_DARK=1` / `BF_LIGHT=1` (force a scheme), `BF_CHAT=<id>` (open that chat), `BF_SHOT_MS=<ms>` (shot delay), `BF_DRAFT=<text>` (prefill the composer, `\\n` = newline), `BF_NEW=<text>` (open the new-message view with that in the To field), `BF_ATTACH=<a:b>` (put files in the composer), `BF_TOP=<n>` (scroll to the top n times, loading older pages), `BF_LINK=<ms>` (keep scrolling to the first link card with a big picture, or to the one whose title has `BF_LINK_TITLE`; use with `BF_TOP`; delete the old shot first, a failed run leaves it behind), `BF_TYPE=<text>` (type into the composer a character at a time, `\\n` = Shift+Enter), `BF_INFO=<ms>` (open the info panel then), `BF_SIDE=<ms>` (press the sidebar button then, narrow window), `BF_TAB=files|links` (with `BF_INFO`: that panel tab), `BF_YT=<video id>` (open the viewer on that YouTube video), `BF_DEMO_FRAME=<picture>` (stand-in first frame for the demo video). Headless frames: `wlr-randr --output HEADLESS-1 --custom-mode WxH` inside `cage` sets the window size; screenshot paths must be relative to the project (the Flatpak sandbox has its own /tmp). Test HiDPI with `wlr-randr ... --scale 2.5` (Peter runs 250%). Screenshot runs are NON_UNIQUE so they never hand off to a running copy. For headless screenshots: `WLR_BACKENDS=headless cage -- sh -c "env BF_DEMO=1 BF_SHOT=... scripts/dev.sh run"`.
- **After each change that's ready for Peter to review, relaunch the app yourself** (it's single-instance, so a new launch just hands off to the old copy): `pkill -x bubblefairy; scripts/dev.sh run` with `run_in_background`. Close it before any headless/screenshot run you start.
- GTK CSS `@media (prefers-color-scheme)` did not fire for an app provider (GTK 4.24), so dark mode is a `window.dark` class set from `gtk-interface-color-scheme` in `ui.rs`.

## Layout

- `src/main.rs`: paths, config file (`key=value` lines), tokio runtime, GTK app startup, CSS loading.
- `src/mac.rs`: backend. `run()` loops connect → serve → reconnect every 5 s. `connect()` resolves the host (plain DNS, then mDNS for `.local` names, because Flatpak runtimes lack nss-mdns), checks the host key (trust on first use, stored in `mac_host_key`), authenticates with the app's ed25519 key (`ensure_key` creates it), execs `<imsg> rpc`, and runs a writer task and a reader task. `dispatch` routes JSON-RPC replies to pending calls and `message` / `watch.overflow` notifications to `Event`s. Images are fetched on separate exec channels with `sips` → JPEG.
- `src/ui.rs`: every widget and all state, on the GTK thread. `on_event` handles backend events, and `render_chats` / `render_conv` rebuild the list and the conversation from state. Only flags that signal handlers touch are kept in `Cell`s, to avoid RefCell re-borrow panics (selecting a row fires `row-selected` synchronously).
- New conversation (ui.rs `start_new`/`end_new`/`send_new`): `new_mode` hides the chat header and messages for a To field plus a suggestions ListBox of 1:1 chats. A typed address sends `Cmd::Send{chat_id: 0, to}`; `State.new_pending` opens the chat when `Event::Chats` lists it (`find_direct_chat`, `same_addr`).
- Older chats: imsg's `chats.list` has only `limit`, no offset, so scrolling the sidebar to its end (`load_more_chats`, adjustment in `build`) asks again for `State.chat_limit` + `CHATS_PAGE` (100) chats and the answer replaces the list (rebuild, scroll kept); `more_chats` goes false when an answer is shorter than the limit. Gotcha: a pinned chat older than the loaded limit has no tile until more are loaded.
- Receipts: `Cmd::Receipts(chat)` reads the delivery / read columns of the chat's newest sent message from chat.db (`parse_receipt`); `State.receipts`, drawn by `conv_widgets` as a small label under that message (`receipt_text`; a red "Not delivered" under any sent message whose chat.db `error` is non-zero, which `add_services` adds to every message), `on_receipt` redraws only the affected messages.
- Times: `rel_time(unix, TimeKind)` is the only formatter; labels showing a time are created through `track_time` (kept in `Ui.time_labels`, rewritten by `refresh_times` at midnight / when the window becomes active on a new day), so a day change needs no rebuild. Failed messages (chat.db `error` != 0): red "!" (`failed_button`) → Try Again → `retry_failed` → `Cmd::Resend` (attachments by their Mac paths), the failed one stays in place (ghost + spinner via `State.resending` while it runs, outline "!" afterwards via `State.resent`, file `resent`); a retried picture's texture is handed to the new message through a `PendingItem::Seed`.
- Read state: `mac::fix_unread` corrects imsg's unread counts from chat.db; `State.seen` (file `data/bubblefairy/seen`) hides dots for chats read in BubbleFairy (`mark_seen`, only while the window is active, so headless runs never mark anything).
- Sending files: `State.outgoing` + `render_attach` (cards above the composer); `pick_files`, a DropTarget on the conversation and `paste-clipboard` add them. `mac::upload` pipes each file into an exec channel (`cat >`) and `send_one` sends it; `Event::Sent` hands back whatever didn't go.
- Pending sends: `send_now` pushes `State.pending` (`Pending{token,chat_id,item}`), `render_conv` draws them faded with a spinner (`pending_bubble`); `settle_pending` (in `on_message`) swaps in the real message and seeds `State.textures` from the local file so the photo shows at once; `Event::Sent` error → `drop_pending` + restore the composer, success → 20 s fallback drop.
- Composer height: set from a Pango layout of the text at the TextView's width (`fit` in `build`), not from the TextView's measure, which ran a line tall while new lines were laid out. Capped at `COMPOSE_MAX`, then scrolls. While it all fits, the vadjustment is pinned to 0: a key press that adds a line scrolls the TextView to the cursor before the field grows, leaving the text ~10 px high. Simulated typing (`BF_TYPE`) doesn't reproduce that.
- Link previews: `preview_row` finds the preview row (imsg folds it into `url_preview`); `link_for` asks the Mac once (`Cmd::Link` -> `mac::link_preview` parses the NSKeyedArchiver plist); Preview pictures under 400x200 px (site logos; Messages shows those as icons too) are measured on the Mac with `sips` (`LinkPreview.image_size`, `is_preview_size`) and drawn small beside the title (`Bubble::thumb`, whole logo on a white tile) instead of across the top. `link_card` draws it as one `Bubble::card` (off-white, image clipped to the bubble outline in bubble.rs; `without_url` strips the link from the message text, which follows as its own bubble). Payload files go through `sips` only: Quick Look hangs on `.pluginPayloadAttachment`, and `fetch_image` has an 8 s watchdog on qlmanage. Photos still need Quick Look because `sips` ignores HEIC rotation (8 of 13 test HEICs came out sideways).
- Avatars: `mac::fetch_contacts`/`parse_contacts` read the Mac's Contacts photos once per connection (`Event::Contacts`); `ui::avatar` draws a `Bubble::disc` photo when `photo_for(handle)` finds one (`addr_key` = lowercase email or last 10 phone digits), else `initials_avatar` (a person icon when the name has no letters); groups use `group_avatar` (member circles in a disc, three plus a "+N" circle past four) in lists and `stacked_avatars` (overlapping row, first on top, "+N" past four) in the conversation header; `pretty_handle` formats +1 numbers everywhere a handle is shown.
- Contacts search and cards: `mac::Contacts` also holds `Person`s (name, org, numbers/emails with labels, postal addresses, birthday; addresses and birthday come from a separate query so a wrong column loses only those), `search()` feeds the To field's suggestions (`ui::suggestions`, contacts without a chat get `a:<addr>` rows), `label()` gives the "mobile/work" chip, `has_imessage()` is true only when chat.db has an iMessage handle for it (registration itself can't be asked). The header avatar opens `show_card`/`card_body`, a Popover parented to the window (parented to a Box it pushes the header's children over), in a ScrolledWindow capped to the room below. Email opens through `gtk::UriLauncher` (`gio::AppInfo::launch_default_for_uri` gave Thunderbird `mailto:///addr`). Our own icons live in `data/icons` (`chat-message-new-symbolic` renders as a red missing-icon glyph in the SDK; added to the icon search path in `main.rs`, needs installing under share/icons in the Flatpak).
- Info panel (ui.rs `build_info`/`wire_info`/`open_info`/`refresh_info`/`on_media`): header "i" button opens an opaque panel that always slides over the chat's right side (never pushes the chat, never widens the window); a click anywhere outside it closes it (window-level capture gesture). Photos / Files / Links tabs, read from chat.db by `mac::chat_media` (`Cmd::Media{kind,offset}`, 30 photos or 60 others a page, "Show more"). Header row (tabs + close) is fixed and only the tab content scrolls; the tabs are our own linked ToggleButtons (StackSwitcher measured far too wide), and at 1 column they become `‹ Photos ›` carets with an invisible twin of the close button so the label stays centred. `info_w(n)` is the slot width for n photo columns (grid cell measures THUMB + 6, header minimum 263 / 223 caret row; CSS margins count inside `set_size_request`), `relayout` picks the largest n that fits over the chat. Thumbnails use `Cmd::Bulk` (2 at a time) so they can't starve the chat's own fetches. Photos/files not on the Mac are marked `missing`. Files download over SSH (`Cmd::Download`) into the cache's `files/` and open with `gtk::FileLauncher`. The Links tab lists only messages with a Messages preview or exactly one trailing link (`mac::single_link`); text comes from `message.text` or the `attributedBody` blob (`text_from_blob`). The header refresh button reloads the loaded messages (`refresh_chat`).
- Pinned chats (ui.rs `pin_key`/`pin_menu`/`toggle_pin`/`render_tiles`): our own list in `data/bubblefairy/pins` (chat `identifier`, one per line, pin order). Pinned chats stay in `chat_list` as *hidden* rows (indexes must match `State.chats`) and show as `FlowBox` avatar tiles (3 per line; one column with names hidden when collapsed) above it inside the sidebar scroller; right-click a row or tile → Pin/Unpin. Dev: `BF_PINS=<key>;<key>` (demo keys = participants joined by `,`). Sidebar search: `search`/`apply_search`/`row_matches` (a `gtk::ListBox` filter func; pinned chats' hidden rows are shown while searching, tiles hidden; dev: `BF_SEARCH=<text>`). Drafts: `swap_draft` in `select`, `State.drafts`.
- Smoothness (the app rule: no hitches): the GTK thread only builds widgets. `bg()` (ui.rs) runs file reads and picture decoding on two worker threads and hands the result back (`decode_file`, `image_done`; contact photos: `prefetch_avatars`/`decode_avatar`, 128 px). A photo on disk shows after a background decode (no spinner), one not on disk gets a spinner and a fetch. `render_conv` builds the whole page in one pass (~28 ms for 150 messages with the pictures decoded elsewhere; building the newest part first and the rest after, in steps or in batches, was tried and only added complexity and a loop that kept loading older pages). The list's preview updates and `mark_seen` change one row in place (`update_row`, `RowParts`); only structural changes rebuild it (`render_chats`, burst-coalesced with `render_chats_soon`). Don't scale while decoding with gdk-pixbuf (`Pixbuf::from_file_at_scale` in a worker made GTK-thread work stall ~20 ms): the Mac sends 900 px chat copies (`mac::CHAT_PX`) instead. Text bubbles use wrap mode `Word`, not `WordChar` (3-4x cheaper to lay out; 150 labels were ~150 ms of the first frame): `WordChar` only when a word is over 30 chars (links). A link preview arriving redraws that one message (`redraw_message`, from `conv_ctx`/`msg_widgets`), not the chat. Headless (llvmpipe) frame times say nothing about paint cost; time your own handlers instead, and the frame clock's phases (`connect_update`/`layout`/`paint`) to see which part of a frame is long.
- Responsive layout (`relayout` in ui.rs, run from a tick callback on width change): window minimum is `COLLAPSED_W + CHAT_MIN`. Below `SIDEBAR_MIN + CHAT_MIN` (700) the sidebar shows avatars only (`COLLAPSED_W`); the header toggle (own `bf-sidebar-symbolic` icon) expands it over the window (divider at width − 8 so its right margin is 14 like the left; the chat fades via `.conv.away`), and the expanded state is forgotten when the window crosses the line. Crossing and the toggle slide the divider (`move_side`, 220 ms). Rows are never rebuilt between modes: each is an Overlay (avatar measured; texts in a clipped slot of fixed width), so only the sidebar width and the `collapsed` CSS class change; "…" truncation (`text_target`/`fit_texts`) is recomputed only after a slide settles. Gotchas: anything that raises the sidebar's minimum width above the divider position at the start of a slide (margin changes, wider header buttons, the loading label in the stack) makes it jump left, so header button margins are constant; keep `side_stack` non-homogeneous.
- Links in chat: `message_parts` shows a preview card when Messages made one; a single trailing link with none becomes `plain_link_card` (host + our link icon `bf-link-symbolic`); several links stay in the text, clickable (`linkify`). `small_picture` picks the larger of the preview's picture and the site icon for the small slot (a very wide picture such as a button graphic loses). Pictures the Mac couldn't give us go in `State.bad_images` and the preview is redrawn without them. Logos draw at their own size or shrunk, never enlarged (`Bubble::thumb`); grid thumbnails are `Bubble::tile`. `Bubble::card` caps its own width (`card_w`) and must set `hexpand(false)` or the title's expand flag stretches it. `watch_for_preview` re-fetches the newest messages (`Cmd::Recent`) at 3/8/20 s for a message whose link has no preview yet. Messages built through AppleScript sends may never get a preview.
- Files in chat (`message_parts` → `file_card` / `video_preview`; info panel Files tab → `file_tile`, a grid like Links): `FileKind` (from MIME, else extension) gives the label and our own icon (`bf-file/video/audio/contact/archive-symbolic`). A file is an off-white `Bubble::card` like links (title = name, `link-site` line = kind · length · size, picture/`glyph(icon)` on the right); a video on the Mac is a photo-sized first-frame `Bubble::photo` with a play disc and length pill; not on the Mac = dimmed, not clickable (imsg can't make the Mac download anything). Clicking copies it over SSH and opens it (`start_download`, shared cache with the panel). What the Mac can give: chat.db has only name, MIME/UTI, size, date (no previews when missing; `transfer_state` is unreliable, check the file); Quick Look (`fetch_image`) draws a PDF's first page and a video's first frame; audio gets only a generic note and vCards hang it, so those use our icon; `Cmd::FileInfo` runs `afinfo` for durations and reads vCard FN/ORG/TEL (`FileInfo`, asked once per file, `State.file_info`, chat redraws on arrival). The Mac has no `timeout` command. Card titles go through `clip_middle` (not label `lines` + ellipsize: that made cards wider than their cap).
- `src/chatscroll.rs`: the chat's scrollable (a `gtk::Scrollable` subclass replacing Viewport), anchored to the bottom: it keeps the gap between the view's bottom edge and the content's end (or stays at the bottom while `stuck`, shared with `Ui.stick_bottom`) inside the same layout pass, so older messages, late pictures and a growing composer never shift what you're looking at. Only the user's own scrolling changes the gap.
- `src/bubble.rs`: `Bubble`, a gtk::Box subclass that draws its own background as one GSK path (body + tail): gradient fill, shadow, top highlight and border all follow the tail. GTK CSS has no clip-path or pseudo-elements, which is why. Colours are in `palette()` (light/dark, read from the window's `dark` class). Inner spacing is set with margins in `new()`, because CSS padding didn't apply to the subclass. Content goes in with `Bubble::add`.
- Photos are `Bubble::photo`: the photo is drawn through the bubble outline, so a photo that ends a sender's run gets a tail showing a sliver of the image. The tail goes only on the run's last item (`end_of_run` in `message_parts`). Every bubble has the same corner radius (no neighbour joining); name and avatar follow the run (`run_prev`/`run_next`), and runs get a tight gap.
- `src/viewer.rs`: photo viewer, a panel of its own in a `stage` Overlay over the whole paned area, edge to edge with the sidebar/chat margins (14 px sides and bottom, 2 px top), 22 px corners, no bevel; the window gets class `viewing` while it's visible, which drops the other panels' shadows/bevels. `Canvas` zooms the photo from its chat spot (`source_rect`) to edge-to-edge fit (240 ms). Items are `(path, Bubble)` from `State.photos`; `refresh()` after every `render_conv` re-finds the current path. Chat copies are capped at `mac::CHAT_PX`; one that hit the cap triggers `Hooks.fetch_full` (`Cmd::Image{full:true}`, `mac::FULL_PX`, cached as `<hash>-full.jpg`) with a canvas spinner until `full_ready`. Items are `viewer::Item` = (key, widget): photos/videos keyed by path (widget = their `Bubble`), YouTube links keyed `yt:<id>:<n>` and played in an embedded WebKit view (`play_youtube`, ephemeral session, `fs=0` etc., web view starts 56 px down so our buttons have their own strip). `ui::open_media` builds the sequence: in the chat = `State.photos` (photos, videos and YouTube cards in order), in the info panel = `info_sequence` (photos + Videos tab tiles, newest first, read back from tiles' widget names `<date>|<key>`). Bounded prev/next (buttons, ←/→, one wheel notch = one item) over loaded items only; it never loads older history (Peter's call). Controls get class `controls` on real pointer motion and drop it after 2.5 s. Keys come from a window-level capture controller in `ui::build`. Dev: `BF_VIEW=1` opens it 0.9 s before `BF_SHOT`, `BF_VIEW=<ms>` at that time (real chats need ~5500).
- Stacks (`photo_stack`): several photos in one message become a card stack (first on top, the rest peeking away from the message's side). Resting spacing is `CARD_STEP` capped to fit; hover spreads to the full chat width (`stack_room`, from the scroller's hadjustment page size), at most side by side. `Ui.stacks` re-lays them when the width changes.
- `src/style.css`: the whole look. Palette tokens live on `:root`, with dark overrides on `window.dark` (`var()` needs GTK ≥ 4.16).
- Saving (ui.rs `save_button`/`save_items`/`queue_save`/`copy_to`): download button beside photos/videos/files, right-click on photos = Copy image / Save as…; folders in config `dir_images`/`dir_files` (Settings group), stored as document-portal paths (field shows the `user.document-portal.host-path` attribute); `State.save_to` holds saves waiting for `Event::Downloaded`; an unusable folder falls back to the dialog.
- Reads from the Mac (mac.rs `cli`): chat list, history, previews, older/newer pages and the search window run `imsg ... --json --no-contacts` as one-off commands (imsg looks up every contact on every call, ~1.2 s, and RPC has no switch for it); names/photos come later from our own Contacts reading and are applied in place (`ui::refresh_identities`, `rebuild_tiles`), never by rebuilding the list. The RPC channel is only for send and watch. sqlite3 on the Mac prints control characters as `^_`, so use printable separators (⁂) in queries.
- Message search (ui.rs `search_changed`/`on_found`/`style_rows`/`begin_find`/`show_goto`/`load_newer`, mac.rs `Cmd::Search/Window/Newer`): see PLAN.md. A chat opened on a hit has `State.find_view` (window around the hit, `more` = newer messages not loaded, so live messages aren't appended); `show_goto` re-finds the target widget every frame for 1.8 s because redraws and late pictures move it (chatscroll is bottom-anchored; `ChatScroll::hold` keeps the view when pages are added below).
